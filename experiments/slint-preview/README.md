# Slint native feasibility preview — F22.02

Separate, non-shipping experiment; depends on the reviewed decision in ADR-001. Uses the existing diagnostic library through the temporary core-probe path dependency; no adapter access, vehicle commands, persistence, runtime network or release packaging. The sole displayed measurement is explicitly synthetic and disappears when the user exits the demo. This is not feature parity or an implemented diagnostic application.

Candidate Slint 1.19.1 runtime and compiler, Winit + software renderer, GPL-3.0-only option. Rust 1.100.0 in repository CI. New dependency tree needs licence and security review. Both the standalone and integrated Cargo.lock were generated by CI and committed byte-for-byte after independent artifact integrity checks. Every platform now builds from the tracked lock with --locked; dependency review remains required. Independent dependency review and the three-OS native CI remain required. The successful Linux bootstrap is not proof of Windows/macOS support or actual window launch. Existing Tauri CI stays unchanged.

From this directory:

    cargo fmt --all -- --check
    cargo clippy --locked --all-targets -- -D warnings
    cargo test --locked
    cargo build --release --locked
    cargo run --locked

Test window launch, resize and keyboard navigation on each OS, verify no physical adapter or file access. No measured startup, CPU or memory claim. Do not distribute this experiment. Next: locked matrix, headless UI-level tests, dependency review and typed core extraction after governance approval.
