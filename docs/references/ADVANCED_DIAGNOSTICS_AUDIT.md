## Additional knowledge to retain

- Adapter diagnostics: counters for timeout, buffer overflow, no data, receive/CAN errors; moving latency metrics per session (measure p50/p95, not only average), automatic troubleshooting with redacted export.
- Protocol capabilities: ELM/STN acceleration is optional and vendor-specific; keep physical bus, adapter host link and diagnostic service independent. Standardized vs OEM diagnostic coverage separate.
- ECU catalog: use lawful data, preserve schema/field provenance, keep source definitions immutable; synthetic XML/JSON fixtures already imported. No ecu.zip in repository; projects.json rights still unverified.
- Headless simulation: feed deterministic synthetic replies through the same parser and policy as production. Never treat fixture data as vehicle measurements.
- Internationalization: source catalogs already imported; imported text/format placeholders must not execute, safety messages reviewed, PT-PT and EN first.
- Test suites inspected: test_doip_connection, test_ecu_data, test_check_ecu_regression, test_elm_iso8, test_doip_identification, test_usb_libusb, test_ecu_file. Port relevant test cases into Rust, not the Python runner. Validate fixtures independently of implementation. In particular do not transplant the routing activation fixture described in ADV-12.
- Scope limits: no credentials, security bypass, arbitrary ECU writes, memory access or safety/emissions deactivation. No copied external runtime. No claims of universal manufacturer support.
